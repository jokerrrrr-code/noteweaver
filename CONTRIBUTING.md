# Contributing

1. Clone the shared repository using your own GitHub account.
2. Create a focused feature branch, such as `feature/pdf-reader`.
3. Make small, meaningful commits with descriptive messages.
4. Include documentation and appropriate tests for your changes.
5. Push the branch and open a pull request explaining the behavior and validation.
6. Ask a teammate to review before merging into `main`.

Agree on shared data contracts before developing separate modules. Integrate early using small sample fixtures; do not wait until the deadline to combine modules.

Keep API keys in local environment variables or an ignored `.env` file. Do not commit keys, personal lecture notes, or course material without permission to publish it. Use original or appropriately licensed test fixtures.

AI-assisted contributions are welcome. Contributors remain responsible for understanding, checking, and accurately describing their changes. Do not claim tests or features work without verifying them.
